# เงินสดย่อย: หน้าอนุมัติ ตั้งเบิก ทำจ่าย ให้หน้าตาและวิธีกดเหมือน Advance

วันที่ 29/10/2026 · branch FE `feat/finance-petty-cash` (worktree `.worktrees/menait-petty-merge`) · BE `merge/petty-cash-main` (worktree `api-ncac-petty-merge`)

## ทำไม

คนที่จะใช้เงินสดย่อย คือหัวหน้า บัญชี และการเงิน ใช้ Advance อยู่ทุกวัน ผู้ใช้ต้องการให้เปิดเงินสดย่อยแล้วเจอหน้าจอและปุ่มแบบเดียวกัน จะได้ไม่ต้องเรียนใหม่ ("เพื่อความง่ายของ User")

## สิ่งที่ผู้ใช้ตัดสินแล้ว

1. **แยกหน้ากันชัดเจน** เงินสดย่อยมีหน้าของตัวเอง ไม่รวมเข้าหน้า Advance
2. **หน้าตาและวิธีกดให้เหมือน Advance มากที่สุด** ต่างกันได้แค่คำ กับขั้นตอนที่ flow ไม่เหมือนกัน
3. **flow ไม่เปลี่ยน** ใช้ flow v2 ตาม `~/Documents/cluade_workspace/petty-cash-requirement/SPEC-FLOW-V2.md`: เปิดใบ → เจ้าของเงินสดอนุมัติจ่าย → ส่งเคลียร์เป็นรอบ → หัวหน้าตามสายงานอนุมัติเคลียร์ทั้งรอบ → บัญชีตรวจทีละใบ → ตั้งเบิกทั้งรอบ → การเงินทำจ่ายทั้งรอบ → ปิด
4. **ตั้งเบิกและทำจ่ายกรอกครบแบบ Advance** ตั้งเบิก = เลขที่ตั้งเบิก + วันที่ตั้งเบิก · ทำจ่าย = เลขที่ทำจ่าย + วันที่โอนเงิน + แนบสลิปโอน · ยอมเพิ่มช่องในฐานข้อมูล
5. ผู้ใช้ยืนยันภาพรวมหน้า (ข้อ "หน้าที่ต้องเปลี่ยน" ข้างล่าง) รวมถึงการให้บัญชีกับการเงินใช้หน้างานเดียวกันแล้วซ่อนปุ่มตามแผนก

## หน้าที่ต้องเปลี่ยน

### 1. อนุมัติเบิกเงินสดย่อย (เจ้าของเงินสด) — `/finance/petty/approvals`
- วางแบบหน้าอนุมัติ Advance: หัวเรื่องซ้าย แถบหัวขวา **รออนุมัติจ่าย · ส่งเคลียร์ · อนุมัติแล้ว**
- แถบรออนุมัติจ่าย: การ์ดทีละใบ แสดงเลขที่ใบ ผู้เปิดใบ ประเภท จ่ายให้ ยอด ช่วงวันที่ เอกสารครบ/ไม่ครบ ไฟล์แนบ · ปุ่ม **ดูรายละเอียดทั้งหมด** (เปิด PettySheet) · **ตีกลับ** · **อนุมัติจ่าย**
- ไม่มีแถบย่อย "อนุมัติแทนได้" เพราะใบอนุมัติได้แค่เจ้าของเงินสดคนเดียว
- กดอนุมัติจ่าย: กล่องยืนยันหน้าตาแบบ Advance แต่มีช่องเพิ่มของเงินสดย่อยครบเหมือนเดิม คือยอดคงเหลือ, หลังอนุมัติใบนี้, ยอดโอนจริง (กติกา 3%), วันที่จ่าย, เลขใบรับสภาพหนี้ (เมื่อมี พจร.) ใส่ DD ถ้าประเภทนั้นต้องใช้
- แถบส่งเคลียร์: ติ๊กหลายใบ + ช่วงวันที่จ่าย + ส่งเป็นรอบ + พิมพ์ใบปะหน้า เหมือนที่มีอยู่ แต่ใช้กรอบ Panel/การ์ดของ Advance
- แถบอนุมัติแล้ว: รายการที่ผ่านมือแล้ว (เทียบแถบ อนุมัติ/ไม่อนุมัติแล้ว ของ Advance) รวมรอบที่ส่งเคลียร์แล้วพร้อมสถานะ
- ตัวเลขสรุป 5 ช่องด้านบนตอนนี้: Advance ไม่มีบนหน้าอนุมัติ ให้เก็บแค่ **ยอดพร้อมอนุมัติ** (ยอดคงเหลือ) เป็นแถบเล็กใต้หัวเรื่อง ส่วนที่เหลือย้ายไปเป็นตัวเลขในแถบ

### 2. อนุมัติเคลียร์เงินสดย่อย (หัวหน้า) — `/finance/petty/clear`
- หน้าแยก แต่วางแบบแถบรออนุมัติเคลียร์ของ Advance: การ์ดหนึ่งใบ = หนึ่งรอบ แสดงเลขรอบ เจ้าของเงินสด วงเงิน จำนวนใบ ยอดรวม วันที่ส่ง · ปุ่ม ดูรายละเอียดทั้งหมด (เปิดหน้ารอบ) · ไม่อนุมัติ (บังคับเหตุผล) · อนุมัติ
- แถบย่อย **รอฉันอนุมัติ / อนุมัติแทนได้** แบบ Advance: "รอฉัน" = คนที่ระบบส่งอีเมลหา (`clear_notify`: ระดับต่ำสุดที่อนุมัติได้ ไซต์เดียวกันก่อน) · "แทนได้" = คนอื่นที่ `can_clear` ผ่าน BE ต้องส่งธงนี้มาในรายการรอบ
- แถบหัวขวา: **รออนุมัติเคลียร์ · อนุมัติ/ไม่อนุมัติแล้ว**

### 3. งานเงินสดย่อย (บัญชี + การเงิน) — `/finance/petty/accounting`
- รวมหน้า `/finance/petty/accounting` กับ `/finance/petty/batches` เป็นหน้าเดียว ชื่อ **งานเงินสดย่อย** (เทียบ "งานเบิกเงิน Advance") · `/finance/petty/batches` redirect มาหน้านี้แถบรอจ่าย · เมนูหน้าแรกรวมสองรายการเป็นรายการเดียว
- โครงหน้าแบบ `app/finance/page.tsx`: ตัวเลขสรุป → แถบตามสถานะ → ตารางเดียว (ค้นหา ตัวกรองทุกคอลัมน์ เรียง Excel ช่วงเดือน) → คลิกแถวเปิดแผงด้านข้าง
- แถบ: **รอบัญชีตรวจ · ส่งกลับแก้ไข · รอตั้งเบิก · รอจ่าย · ปิดแล้ว · ทั้งหมด**
  - แถวในแถบ รอบัญชีตรวจ / ส่งกลับแก้ไข = **ใบ** · แถวในแถบ รอตั้งเบิก / รอจ่าย / ปิดแล้ว / ทั้งหมด = **รอบ** · คอลัมน์ของตารางเปลี่ยนตามชนิดแถว (การตัดสินของผู้เขียน)
- **ไม่มีปุ่มในแถวแล้ว** ทุกการกดอยู่ในแผงด้านข้างแบบ Advance (ผ่าน/ตีกลับ, ตั้งเบิก, จ่ายเงิน)
- ซ่อนปุ่มตามแผนกแบบ Advance: บัญชี (`is_accounting`) = ตรวจ + ตั้งเบิก · การเงิน (`is_treasury`) = จ่ายเงิน · แอดมินได้ทุกปุ่ม · ด่านจริงยังอยู่ที่ BE

## หลังบ้าน (api-ncac)

- `fin_petty_batches` เพิ่ม `voucher_date DATE`, `pay_doc_no VARCHAR(50)` · ใส่เพิ่มในไฟล์ `scripts/migrations/2026-10-29_petty_flow_v2.sql` แบบ `ADD COLUMN IF NOT EXISTS` (ไฟล์นี้ยังไม่เคยรันบน prod) แล้วอัปเดต model

- รายการรอบสำหรับหัวหน้า (`GET /batches?view=clear`) ส่งธง `is_primary` ต่อรอบ (จาก `clear_notify`) ให้แถบย่อยรอฉัน/แทนได้

- สลิปโอนของรอบเก็บ S3 ที่ `menait-service/<batch_no>/pay/` · route `/api/uploads3` ต้องรับเลขรอบ (รูปแบบ `XX-XXX-YYMM-B<n>`, ตอนนี้ `FORM_ID_PATTERN` ไม่รับ) และจำกัดให้การเงิน/แอดมินอัปโหลดโฟลเดอร์ pay ของรอบได้เท่านั้น · ห้ามหลวมจน path param พาไป route อื่นได้ (เคยมีบั๊กนี้ ดู memory)

## ตัดสินเพิ่มหลังอ่านทวน (การตัดสินของผู้เขียน 29/10/2026)

- **DD ไม่อยู่ในกล่องอนุมัติ** ใส่หลังอนุมัติเหมือนเดิม (BE รับ DD เฉพาะใบที่อนุมัติแล้ว และบังคับตอนสร้างรอบ) · การ์ดในแถบส่งเคลียร์มีปุ่ม ใส่ DD / แก้ DD สำหรับประเภทที่ต้องใช้
- **ประวัติรอบ** สร้างจากคอลัมน์ของรอบเอง (ส่ง, อนุมัติ/ไม่อนุมัติ + เหตุผล, ตั้งเบิก, จ่าย, ปิด) ไม่แก้ตาราง fin_petty_logs · ตั้งเบิกเขียน log ลงทุกใบในรอบด้วย
- **แก้เลขเอกสารได้แบบ Advance** (EditDocNumbersButton): `POST /batches/{id}/doc-numbers` แก้เลขที่/วันที่ตั้งเบิก (VOUCHERED, CLOSED) และเลขที่ทำจ่าย (CLOSED) · ไม่มีปุ่มตีกลับตั้งเบิกแบบ Advance เพราะเปลี่ยน flow
- **บั๊กเลขรอบชน** เลขรอบนับต่อกองทุนแต่คอลัมน์ไม่ซ้ำต่อสาขา-ฝ่าย → นับตาม prefix สาขา-ฝ่าย-ปีเดือน
