# แผนรอบสอง — preset เอกสารตามประเภท + ปรับ 4 ประเภทจากเอกสารจริง

ต่อจากแผนรอบแรก (15 งาน ทำครบแล้ว) · ฉบับ 2026-10-12
อ้าง `DESIGN-TYPES.md` ซึ่งถอดจากเอกสารจริงทั้ง 4 ไฟล์ใน `Reference_data/เงินสดย่อย/`

**เป้าหมาย** — เลือก "ใบสำคัญจ่ายเงินสดย่อย" → เลือกประเภทการเบิก → ระบบแสดงชุดเอกสารของประเภทนั้น
(ต้องแนบอะไร จะพิมพ์อะไร กฎอะไร) แล้วให้กรอกตามฟอร์มที่ประเภทนั้นกำหนด

**ข้อสั่งที่รอบนี้ยึด**
- ไม่มีเรื่องหักภาษี ณ ที่จ่ายในระบบนี้
- ค่าทางด่วน = โครงเดียวกับค่าเดินทาง ต่างที่ใช้ใบเสร็จตัวจริง
- ค่าซ่อมฉุกเฉิน = โครงเดียวกับค่าชั่งน้ำหนัก

## งาน C — แผง "ชุดเอกสารของประเภทนี้" (ของใหม่ที่ผู้ใช้ขอ)

**ไฟล์:** `app/finance/components/petty/DocumentPreset.tsx` (ใหม่) ·
`lib/finance/petty-preset.ts` (+ `.test.ts`) · ต่อเข้า `app/finance/petty/new/page.tsx`

เมื่อเลือกประเภทแล้ว ขึ้นแผง 3 กล่องทันที อ่านจาก `spec` ตัวเดียวกับที่ด่านใช้

| กล่อง | ที่มา | ตัวอย่าง (ค่าชั่งน้ำหนัก) |
|---|---|---|
| ต้องแนบ | `spec.attachments` | ☐ ใบชั่งน้ำหนัก (สำเนา) ☐ หลักฐานโอนเงิน · ○ อื่น ๆ (ไม่บังคับ) |
| ระบบจะพิมพ์ให้ | `spec.prints` | ใบสำคัญจ่าย · ใบรับรองแทนใบเสร็จ · ใบรับสินค้า DD |
| กฎของประเภทนี้ | `spec.rules` + `spec.duplicate_check` | ยอด ≥ 500 ต้องมีเลข DD ก่อนส่งบัญชี · บัตรชั่งใบเดิมของรถคันเดิมเบิกซ้ำไม่ได้ · รถคันเดิมใน 7 วันจะเตือน |

**ฟังก์ชันล้วนที่ต้องเขียน** (`petty-preset.ts`)
- `requiredDocs(spec)` → `{key,label,required}[]` เรียงบังคับขึ้นก่อน
- `printableDocs(spec)` → ชื่อไทยของ `PETTY_VOUCHER`/`RECEIPT_SUBSTITUTE`/`DD`
- `ruleSentences(spec)` → ประโยคไทยจากกฎ เช่น `total >= 500 + dd_no` → "ยอดตั้งแต่ 500 บาท ต้องมีเลขที่ใบรับสินค้า (DD) ก่อนส่งบัญชี"
- ติ๊กเขียวเมื่อผู้ใช้แนบไฟล์หมวดนั้นแล้ว (รับ `counts` เข้ามา)

- [ ] เทสต์ ~12 ข้อ: spec ว่างไม่พัง · หมวดบังคับขึ้นก่อน · ประโยคกฎอ่านรู้เรื่อง · ประเภทที่ไม่มีใบรับรองไม่โชว์
- [ ] เขียน lib ให้ผ่าน แล้วทำ component + ต่อเข้าหน้าเปิดใบ
